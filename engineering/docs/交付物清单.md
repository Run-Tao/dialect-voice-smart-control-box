## 六、必须在答辩前解决的问题

0. **下一版路线已在 `docs/v5方案设计.md`**（S0 于 2026-10-31 完成，S3 与 S4 于 2026-11-01 完成，
   S4(b) 于 2026-11-03 完成，S5 部分完成；S1/S2/S6–S7 未实施）。核心变化：两遍识别、
   风险-覆盖拒识、设备状态先验、动作优先播报，以及用**公开真人粤语语料**
   建立「真实域误接受率」指标——S0 已用 FLEURS（CC BY 4.0）在不自采真人数据的前提下
   测出该指标，S3 已把该指标从 0.3110 压到 0.0660，部分回应下面第 1、2 条的质疑。
   S4(b) 把两遍流式管线接上线并测出感知延迟（动作 P95 142.7 ms，达标）；S5 的对话补救
   机制在**部署口径**下收益为 0.0000，未达成验收判据（见下面第 5 条）。
1. **真人数据是硬门槛**。现有全部命令识别数字来自 edge-tts 合成粤语；
   合成与真人之间的域差距已由 S0 实测：真实域 FAR 0.3110 对合成 0.125，约 2.5 倍，
   置信区间不重叠（`docs/v5方案设计.md` §9.1）。真人**命令正样本**仍为 0，
   真人说话人上的命令识别率仍未知。在拿到真人数据前，PPT 与报告中的
   命令识别数字必须标注为合成语料结果。**S3 的覆盖率 0.8455 同样只是合成侧代理**
   （见 §9.2 限制 1、风险登记册 R-12）。
2. **真实域误接受率：短板已定位并给出可部署方案，但尚未上线**（S0 实测 + S3 实测）。
   - 现状部署（单 max-prob 阈值 0.945）：FAR **0.3110**，危险误动作率 **0.1437**
     （2744 段 FLEURS 真人粤语非命令语音）。合成 unknown FAR 0.125 **不可用作安全指标**。
   - 抬阈值不可行：FAR 0.15 → 0.10 之间覆盖率从 0.6159 断崖到 0.0023。
   - **S3 已解决信号选择问题**：`maxprob ≥ 0.3092 AND ood ≥ −0.0202`（ood = 嵌入 kNN
     距离取负，阈值**只在合成侧标定**）→ FAR **0.0660** CI [0.0571, 0.0761]、
     危险误动作率 **0.0201**、合成覆盖率 0.7864 → **0.8455**。两个轴同时改善，
     证明断崖来自信号选错而非模型容量（`docs/v5方案设计.md` §9.2）。
   - **仍未完成**：kNN 参照池下发的 500 条 f16 已把体积压到 250 KB（≤ S2 的 300 KB 预算）；
     真人命令覆盖率未测（R-12）；有限样本高概率保证（Hoeffding / PAC-Bayes）未实现，
     当前只有 Wilson CI。**S4 已把规则接入 `src/realtime.py` 并下发工件**
     （`runtime/models/v3_selective_gate.json` + `v3_knn_pool.npz`，阈值与池成对下发）。
3. **窗帘两类命令最弱**（测试集 0.6849 / 0.7561），
   验证集 0.9477 与测试集 0.8799 差 6.8 个百分点，说明表达组覆盖不均衡。
4. **现场联动链路未在实机验证**。智能音箱对播放音频的识别稳定性、
   树莓派上的真实延迟，都还是未知数，演示前必须留好继电器与录播两条退路。
5. **快速端点会把话切早**（S4(b) 实测，R-14）。语料按默认 390 ms 挂起切，部署按 120 ms 切，
   480 条里 **18 条被切早**，其中 8 条执行且**全部执行错命令**（CURTAIN_OPEN → CURTAIN_CLOSE）；
   未截断样本的错误执行率只有 0.0674。恢复挂起能消除截断但动作延迟回到约 400 ms，
   **300 ms 预算与「不切早」在这份语料上互斥**。落地前不得把 300 ms 预算当作已经无代价地拿到。
6. **S5 的对话补救在部署口径下没有收益**（S5 实测，R-15）。离线口径易混对增益 +0.0709，
   走部署路径（`scripts/eval_dialog.py --mode stream`）增益 **0.0000**，会话成功率
   0.7371 < 离线 0.7992，S5 的验收判据**未达成**。三条原因已量化：输入截断、关键词偏置
   把错候选锁死、一致性规则过严（161 条两遍不一致里 148 条本来判对却被降级）。
   需要重定标 `consistency_margin` 与偏置幅度后，在 `docs/dialog_eval_stream.json` 上复测，
   不能拿离线口径的数交差。
