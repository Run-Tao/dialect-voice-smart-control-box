# 技术路线修订说明

日期：2026-10-30
适用范围：`DialectVoice_Engineering`（本科工程导论项目）及其依赖的 `DialectVoice_Research`

本文所有数字均为本项目代码在本地实跑所得，可通过 `docs/` 下的评估工件复现：
`pipeline_eval.json`（部署管线）、`ablation_old_model.json`（旧模型消融）、`threshold_curve.json`（阈值曲线）。

## 1. 修订原因

开题报告与项目建议书（2026-10-14/15 版）的技术路线是：

> 方言语音 → VAD → MFCC → SVD → **方言到普通话特征映射** → 余弦相似度匹配 → 普通话指令 → 智能音箱

本项目在工程化过程中用自有实验数据核对了这条路线，结论是：**特征层映射这条主线不成立，必须改成语义层映射。**
同时发现工程侧长期缺少 VAD 与实时闭环，导致开题报告里描述的系统在代码中并不存在。

以下三条是本次修订的直接依据。

## 2. 依据一：特征层映射的下游识别准确率等于随机水平

`DialectVoice_Research/outputs/tts_mapping_experiment.json`（30 组方言-普通话语义配对，按表达组划分）：

| 方法 | 训练 RMSE | 训练 mean cosine | **下游命令识别准确率** |
|---|---:|---:|---:|
| OLS | — | — | 报错 `某个元素在所有训练对上方差为0，无法估计斜率` |
| Ridge | 0.0253 | 0.9990 | **0.1667** |
| 直接分类基线 | — | — | 0.1667 |

6 类命令的随机基线是 1/6 = 0.1667。也就是说：回归把方言特征拟合到普通话特征上非常"准"
（余弦 0.999），但映射后的特征对**命令判别**没有任何信息量。

原因不是调参不足，而是方法本身：回归是在全数据上拟合一个统一的方言→普通话变换矩阵，
它只约束了特征空间的整体形态，没有按命令类别条件化，因此类别间的判别边界在映射后被抹平。

**结论：转换必须发生在语义层（命令标签），不能发生在特征层。**

## 3. 依据二：直接分类路线有效，且有现成可部署模型

`DialectVoice_Research` 第三阶段（v3/v3.1）已在固定测试集（483 条未见表达组）上验证：

| 模型 | Test Acc | Macro-F1 | 说明 |
|---|---:|---:|---|
| MFCC+DTW 基线 | 0.5901 | 0.5921 | 二期主模型 |
| 经典判别式（MFCC+Δ+logreg） | 0.6749 | 0.6706 | |
| **CNN 3 种子集成** | **0.9048** | **0.9022** | 1.35 MB，纯 numpy 推理 16–18 ms/条 |
| CNN + 经典融合 | 0.9151 | 0.9126 | 实验最佳，未部署 |

模型工件 `v3_cnn_ensemble.npz` 已是纯 numpy 推理，可在树莓派上离线运行，
无需 torch、无需联网。

## 4. 依据三：线上输入分布与训练分布不一致（本项目新发现）

项目建议书技术路线的第一步是 VAD，但代码里此前**没有任何 VAD 实现**，
识别入口用的是固定 1.2 s 滑窗。本项目补上 VAD 后实测（旧模型 `v3_cnn_ensemble.npz`，
未裁剪语料 `wav16k_v3/edge` 全量 2238 条，合成 TTS 粤语，标签取自文件名）：

| 输入方式 | argmax 准确率 | 接受率 | 接受样本准确率 | 未知指令误接受率 |
|---|---:|---:|---:|---:|
| 整段送入（无 VAD） | **0.9768** | 0.9517 | 0.9925 | 0.3611 |
| VAD 端点检测 | 0.7395 | 0.6819 | 0.9207 | 0.4444 |

分命令看，VAD 的伤害集中在短命令上：

| 命令 | 无 VAD | 有 VAD |
|---|---:|---:|
| LIGHT_ON | 0.9893 | **0.1716** |
| LIGHT_OFF | 0.9705 | **0.4960** |
| CURTAIN_CLOSE | 0.9732 | 0.8472 |
| ALL_OFF | 0.9598 | 0.9920 |
| STATUS_ALL | 1.0000 | 0.9759 |

排查后定位到根因：**模型是在带 TTS 尾部静音的整段 WAV 上训练的**（语料里 0.5–1.0 s 尾部静音），
而 VAD 输出的是紧贴语音的音频。特征做整句 CMVN，尾部静音稀释了均值/方差，
输入分布一变，模型失效。

验证实验（LIGHT_ON + LIGHT_OFF 共 746 条）：

| 输入 | 准确率 |
|---|---:|
| 原始整段 | 0.9799 |
| VAD 裁剪 | 0.3338 |
| VAD 裁剪 + 补 0.7 s 静音 | 0.9705 |

补静音能恢复精度，说明问题确实出在"训练/部署输入分布不一致"，
而不是 VAD 切段本身切坏了语音。

**处理方式：不是在线上补静音（那是把 bug 当特性），而是让训练输入与部署输入同源**——
用同一个 VAD 处理训练语料得到 `manifest_yue_v3_1_vad.csv`，在裁剪后的语料上重新训练，
得到部署模型 `v3_cnn_ensemble_vad.npz`。

## 5. 修订后的技术路线

```
方言语音 → VAD 端点检测 → log-mel40+Δ（整句 CMVN）→ 1D-CNN 3 种子集成
        → 温度标定置信度 → 阈值拒识 → 语义层映射（命令标签 → 普通话指令）
        → 扬声器播放普通话指令 → 智能音箱执行
                              ↘ 备用通道：串口 ESP32-S3 / 继电器直控
```

关键变化：

1. **删除** MFCC → SVD → 回归映射 → 余弦匹配 这条链；
2. **新增** VAD 端点检测（自适应噪声底 + 静音挂起 + 前后裁剪）；
3. **新增** 温度标定置信度与阈值拒识（低置信度不执行，提示重说）；
4. **保留并强化** 语义层映射：命令标签 → 普通话指令文本 → 预录音频播放，
   这是智能音箱外接场景真正需要的"转换"；
5. **训练与部署同源**：训练语料由部署同款 VAD 生成。

## 6. 修订后的实测结果（部署模型 + 同源语料）

部署模型 `v3_cnn_ensemble_vad.npz`，阈值 0.945（同源裁剪语料，`manifest_yue_v3_1_vad.csv`）：

| 集合 | 条数 | argmax 准确率 | 接受率 | 接受样本准确率 | 未知指令误接受率 | 单条延迟 |
|---|---:|---:|---:|---:|---:|---:|
| 验证集 | 440 | 0.9477 | 0.7864 | 0.9942 | 0.125 | 13–16 ms |
| **测试集（未见表达组）** | **483** | **0.8799** | 0.7598 | **0.9319** | **0.125** | 13–16 ms |

测试集分命令 argmax 准确率：

| ALL_OFF | STATUS_ALL | LIGHT_OFF | LIGHT_ON | CURTAIN_OPEN | CURTAIN_CLOSE |
|---:|---:|---:|---:|---:|---:|
| 0.9157 | 1.0000 | 0.9595 | 0.9462 | 0.7561 | **0.6849** |

需要如实指出的两点：

1. **验证集 0.9477 与测试集 0.8799 相差 6.8 个百分点**，且弱点集中在窗帘类命令
   （CURTAIN_CLOSE 0.6849、CURTAIN_OPEN 0.7561）。这说明当前按表达组划分的两组难度并不均衡，
   窗帘类表达组的多样性不足，**第 3 周真人数据采集时需要优先补这两类的表达变体**。
2. 验证集 0.9477 与训练报告 `outputs/v3_train_vad.json` 记录的 `ensemble_val.accuracy`
   完全一致，说明部署管线的特征提取与训练管线逐样本一致，不存在实现漂移。

与旧方案相比的效果变化：

| 指标 | 旧模型 + 未裁剪语料（线上直接跑会坏） | 部署模型 + 同源语料 |
|---|---:|---:|
| 测试/全量 argmax 准确率 | 0.7395（带 VAD） | 0.8799 |
| LIGHT_ON | 0.1716 | 0.9462 |
| LIGHT_OFF | 0.4960 | 0.9595 |
| 未知指令误接受率 | 0.4444 | **0.125** |

即：同源重训不仅修好了短命令的整体崩溃，未知指令误接受率也从 0.4444 降到 0.125。

## 7. 拒识阈值的取值与取舍

阈值选取脚本 `scripts/calibrate_threshold.py`，只用验证集（440）与未知校准集（36），
测试集不参与选择。

选定工作点：**阈值 0.945，温度 0.5**，验证集覆盖率 0.8114，校准集误接受率 0.1389。

需要说明的是取舍：`DialectVoice_Research` 原定业务目标是「已知命令覆盖率 ≥ 0.85 且
未知指令误接受率 ≤ 0.08」，但在这批数据上**没有同时满足两者的点**
（阈值 0.985 时覆盖 0.6545、误接受 0.0833）。因此把业务约束放宽为
「覆盖率 ≥ 0.80 且误接受率 ≤ 0.15」，并在 `v3_thresholds_vad.json` 中显式记录了这一取舍。
这属于**产品安全目标与当前数据能力之间的缺口，不是算法参数问题**，
需要靠补采难负样本（易混指令）来真正改善。

## 8. 连带需要修订的内容

| 项目 | 原表述 | 修订后 |
|---|---|---|
| 命令集 | 8 条（灯/风扇/空调/温度） | 6 条（LIGHT_ON/OFF、CURTAIN_OPEN/CLOSE、ALL_OFF、STATUS_ALL），与模型训练语料一致；扩展到风扇/空调需先补语料再训练 |
| 硬件 | 树莓派 4B + 继电器 + IR | 端侧推理（PC 或树莓派）+ 麦克风 + 扬声器 + ESP32-S3（LED/舵机/OLED）；继电器保留为备用 |
| 数据 | 2–3 位方言使用者，每命令 30–50 次 | 仍需真人数据，现有基线与全部数字均来自合成 TTS，必须补真人采集后才能下真实结论 |
| 评价指标 | 含"映射均方根误差" | 删除该指标（映射已取消），保留识别准确率、接受样本准确率、误接受率、端到端延迟、执行成功率、误触发率、总成本 |
| 对比实验 | MFCC+DTW 基线 vs MFCC+SVD+回归映射 | MFCC+DTW 基线 vs log-mel+CNN；并单列"VAD 前后"消融 |
| 单条延迟 | "20 ms 量级" | 实测 13–16 ms（特征提取 + 推理，不含 VAD 等待与执行） |

## 9. 尚未解决、需要真人数据才能回答的问题

1. 合成 TTS 与真人粤语之间的域差距有多大；
2. 未见说话人（真人）上的识别率；
3. 未知指令误接受率能否降到业务可接受水平（当前合成集上 0.125，仍是短板）；
4. 真实噪声环境（电视/风扇）与远场（1–3 m）下的表现；
5. 端到端延迟的真实值（含 VAD 等待静音挂起的时间与扬声器播放时长）。

以上五项在拿到真人语料前不得给出结论，也不得写进答辩 PPT 作为性能承诺。
