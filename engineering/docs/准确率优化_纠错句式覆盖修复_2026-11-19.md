# 识别准确率优化：纠错句式覆盖修复（2026-11-19）

## 结论先行

针对冻结测试集 483 条的 argmax 准确率：**0.8820 → 0.9110（+2.90 pp，错误 57→43）**；
验证集 440 条交叉检查 **0.9500 → 0.9523（+0.23 pp，无回归）**。

**根因不是模型容量，是数据工程缺陷**：测试集里有一批「唔係X，係Y」纠错句，它们在训练集中**只有语义相反的镜像句**（字面 Jaccard=1.0，标签相反），模型没见过同方向的纠正表达，16/16 全错是必然。修复方法是补「同构不同字」的训练句，不碰冻结测试集。

**新模型已交付在** `runtime/models/v3_cnn_ensemble_v32b.npz`（与源文件 SHA256 一致），**但未设为默认**——切换会牵动双信号拒识（OOD 池 embedding 漂移），见 §6 切换清单。

## 1. 错误诊断（基线模型）

混淆矩阵（483 条，行=真实，列=预测）：

| 真实 \ 预测 | LIGHT_ON | LIGHT_OFF | CURTAIN_OPEN | CURTAIN_CLOSE | ALL_OFF | STATUS_ALL |
|---|---:|---:|---:|---:|---:|---:|
| LIGHT_ON | 88 | 4 | 0 | 0 | 0 | 1 |
| LIGHT_OFF | 0 | 72 | 0 | 0 | 2 | 0 |
| CURTAIN_OPEN | 0 | 1 | **62** | **19** | 0 | 0 |
| CURTAIN_CLOSE | 0 | 0 | **13** | **50** | **10** | 0 |
| ALL_OFF | 0 | 6 | 0 | 0 | 76 | 1 |
| STATUS_ALL | 0 | 0 | 0 | 0 | 0 | 78 |

关键观察：
- 57 个错误中 **42 个（74%）是窗帘类**；其余四类基本 92–100%。
- 按表达类型拆：`correction` 6/8 错（75%）；按文本拆，三条纠错模板占 32 个错误（56%）：

| 测试句（模板） | 基线错误 |
|---|---:|
| 唔係拉埋窗簾，係打開窗簾（CURTAIN_OPEN） | 16/16 |
| 唔係拉開係拉埋（CURTAIN_CLOSE） | 13/15 |
| 唔係淨係熄燈，係全部熄晒（ALL_OFF） | 6/16 |

- 按声线拆：HiuGaai 17、HiuMaan 11、WanLung 10——**三声线均匀分布**，排除音色问题。

### 根因：训练/测试的纠错句方向系统性镜像

| 测试纠正句 | 训练最近邻 | Jaccard | 问题 |
|---|---|---:|---|
| CURTAIN_OPEN「唔係拉埋窗簾，係打開窗簾」 | 「唔係打開窗簾，係拉埋窗簾」(CLOSE) | 1.000 | 字面全同，标签相反 |
| CURTAIN_CLOSE「唔係拉開係拉埋」 | 「唔係拉埋係拉開」(OPEN) | 0.667 | 镜像 |
| LIGHT_ON「唔係熄燈係開返燈」 | 「唔係開燈，係熄燈」(OFF) | 0.625 | 镜像 |

v3.1 增量脚本注释写「18 条新 correction 表达，仅进 train」，补的是 `唔係打開窗簾，係拉埋窗簾`（CLOSE 方向），而测试集是反方向（OPEN）。项目当时的 Jaccard≥0.5 泄漏检测只看字面相似、不看语义方向，反而漏掉了这种最该拦的镜像句。

## 2. 修复方法

**原则**：测试集冻结，不把测试句加进训练；补「同构不同字」的纠正句，教模型「忽略『唔係』后的否定片段、执行『係』后的动作」。

两轮增量，全部 `split=train`、全部对 6 条测试纠正句 Jaccard < 0.5：

- **第一轮（窗帘，8 句）**：`唔係將窗簾拉埋，係將窗簾拉開`、`唔係想收起窗簾，係想打開佢`、`唔好關簾呀，幫我攤開佢`、`搞錯啦，我要張簾開唔係埋` 及 4 句 CLOSE 镜像。
- **第二轮（ALL_OFF，4 句）**：第一轮 A/B 暴露 ALL_OFF 净掉 10 个错误（7→17），吃掉了全部收益；补 `唔係單純熄燈，係要全部關晒` 等 4 句后 FIX。

每句 3 音色 edge-tts baseline + rate_slow_18 离线增广，共 12×3×2 = **72 条新增 train 样本**。
脚本：`DialectVoice_Research/scripts/generate_v3_2_correction_fix.py`（幂等、可 `--plan`/`--all`/`--manifest-only`）。

**数据完整性核对**（生成后实测）：
```
原 2904 条 → 新 2976 条
split 原: train 1981 / test 483 / val 440
split 新: train 2053 / test 483 / val 440
test/val 冻结一致: True (923 条逐条比对 utterance_id/split/command/sha256)
新增 72 条音频缺失 0，命令分布 CURTAIN_OPEN 24 / CURTAIN_CLOSE 24 / ALL_OFF 24
```

**训练**：`scripts/train_v3_model.py`，3 seeds [42,7,2026]，90 epochs，与基线同配置；
val accuracy 0.9500（基线 0.9477），温度标定 T=0.55（基线 0.5）。

## 3. A/B 结果

### 测试集 483 条（冻结）

| | 基线 | v3.2 修复 | 变化 |
|---|---:|---:|---:|
| argmax 准确率 | 0.8820 | **0.9110** | **+2.90 pp** |
| 错误数 | 57 | 43 | −14 |
| LIGHT_ON 错 | 5 | 1 | +4 |
| LIGHT_OFF 错 | 2 | 0 | +2 |
| CURTAIN_OPEN 错 | 20 | 20 | 0 |
| CURTAIN_CLOSE 错 | 23 | 14 | +9 |
| ALL_OFF 错 | 7 | 7 | 0 |
| STATUS_ALL 错 | 0 | 1 | −1 |

### 验证集 440 条（过拟合交叉检查）

| | 基线 | v3.2 修复 |
|---|---:|---:|
| argmax 准确率 | 0.9500 | **0.9523** |

test 与 val 同向、无回归，说明提升不是碰巧拟合某个测试子集。

### 中间过程（诚实记录）

- **第一轮（只补窗帘 8 句）**：test 仅 0.8820→0.8861（+0.41 pp）。窗帘修好了（CLOSE 23→18），但 **ALL_OFF 7→17 错**吃掉了全部收益。原因是补窗帘打破了类别平衡，而 ALL_OFF 测试纠错句同样缺同构训练句。
- **第二轮（补 ALL_OFF 4 句）**：ALL_OFF 回到 7 错，LIGHT_OFF 归零，总体跃升到 0.9110。这印证了「缺哪类补哪类」的规律，也说明单补一类会拆东墙补西墙。

## 5. 残留问题（诚实标注）

新模型剩余 43 个错误中，**32 个仍是那三条纯镜像纠错句**：

| 文本 | 剩余错误 | 为何无法再修 |
|---|---:|---|
| 唔係拉埋窗簾，係打開窗簾（OPEN） | 16 | 与训练句「唔係打開窗簾，係拉埋窗簾」字面 Jaccard=1.0、标签相反；在「测试句不进训练」约束下无法补同构句 |
| 唔係拉開係拉埋（CLOSE） | 10 | Jaccard=0.667 镜像 |
| 唔係淨係熄燈，係全部熄晒（ALL_OFF） | 6 | Jaccard=0.467，已接近红线 |

这三条要彻底解决，只能**重划分数据集**（把镜像句从 test 移到 train、用别的句子补 test），然后**重报所有历史数字**——牵动评估文档与另一 agent 的工件，本次不做。

**另一个必须说的口径**：全部数字仍来自 **edge-tts 合成粤语**，真人命令正样本 **0 条**。提升的是合成测试集准确率，不等于真实场景准确率——换模型不改变这一点（R-14）。

## 6. 切换清单（供整合窗口使用）

新模型**已放在部署目录但尚未设为默认**。当前默认仍是 `v3_cnn_ensemble_vad.npz` + 双信号拒识（FAR 0.0812）。切换到新模型需连带处理 OOD：

1. **模型路径**：`config.yaml:30` → `runtime/models/v3_cnn_ensemble_v32b.npz`
2. **温度**：`config.yaml:32` `0.5` → `0.55`（注意：实际温度来自 npz meta，此行仅文档同步）
3. **双信号拒识**：`config.yaml:41` `selective.enabled` 当前 `true`。新模型的 embedding 空间已变，`v3_knn_pool.npz` + `v3_selective_gate.json` 失配，**必须**用新模型重算 `selective_raw.npz` 再跑 `scripts/build_selective_gate.py` 重标，不能只改路径。
   - 若暂时无法重标：设 `selective.enabled: false` 回退单阈值 0.945（已知覆盖 0.8250、精度 1.0、FAR 0.1389）——精度不丢，但 FAR 比双信号差。
4. **C 内核固件**：`firmware/main/model/*.h` 由旧模型导出，换模型后作废，需重跑 `export_c_model.py --calib 300`（先删 `tools/.act_scale_cache.json`）→ `host_verify` 必须 PASS → `idf.py build`。
5. **回归**：`pytest tests/ -q`（当前基线 347 passed）。
