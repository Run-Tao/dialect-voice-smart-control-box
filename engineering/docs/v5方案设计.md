## 1. 问题定义

### 1.1 项目目标

让只说方言（粤语）的用户通过语音控制家居设备（灯、窗帘），系统在端侧离线识别命令、
以普通话播报确认、并驱动硬件执行。

### 1.2 需求

| 编号 | 需求 | 约束来源 |
|---|---|---|
| R1 | 识别有限命令集，容忍表达多样性 | 目标 |
| R2 | 端侧、离线、低成本、低延迟 | 目标（树莓派 + ESP32） |
| R3 | 不得把非命令语音当命令执行 | 安全 |
| R4 | 反馈可被方言用户理解 | 目标（普通话播报） |
| R5 | 课程可交付：可复现、可演示、有测试 | 课程性质 |
| R6 | 换说话人 / 换房间 / 有噪声时仍可用 | 真实使用 |
| R7 | 新增命令的成本可控 | 可维护性 |
| R8 | 指标可信，限制如实说明 | 学术诚信 |

### 1.4 基线的四个结构性弱点

1. **合成域过窄**：训练与测试都来自少量 edge-tts 音色，说话人多样性远低于真实家庭；
   0.8799 这个数只在合成域内成立。
2. **真实域风险完全未测**：FAR 0.125 是在 72 条**合成**未知指令上得到的，
   真人语音（含电视、闲聊、口音）下的误触发率是未知数，而这是 R3 的核心。
   **S0 已实测**：真实域 FAR 0.3110（见 §9.1），域差距约 2.5 倍，本弱点由「未知」变为「已测且不达标」。
3. **拒识是单点阈值**：0.945 是一个全局标量，没有风险-覆盖曲线，
   无法回答「要把 FAR 压到 2% 需要牺牲多少覆盖率」。
   **S0 已实测**：能回答，且答案是覆盖率断崖（FAR 0.15 → 0.10 时 0.6159 → 0.0023，见 §9.1），调阈值不可行。
4. **延迟结构不合理**：算法只占 10 ms，但用户等 2.0 s——时间花在等静音（400 ms）
   和等播报播完（1.6 s）上，而播报期间设备其实早已可以动作。

## 2. 三轮方案演进

| 轮次 | 创新点所在 | 主要结论 |
|---|---|---|
| v4 | 交互与流程 | 提出快判/复核双通道、三态决策、主动澄清、动作优先播报 |
| v4.1 | 上下文与评估 | 加入设备状态先验、代价决策、会话级评估；砍掉流式解码器、是/否模型、conformal 包装 |
| **v5** | **数据与度量** | 用多说话人 TTS 扩容解决域窄；用公开真人粤语建立**真实域误接受率**指标；拒识、两遍架构、端侧适配全部对齐到有文献支撑的做法 |

v5 的判断依据：对课程项目而言，**能产出别人没有的数字**比再堆一层模型更有价值；
而「真实域 FAR」恰好是本项目最大质疑（全合成）的正面回应，且不需要硬件、不需要自采真人数据。

## 4. 路线选型

| 维度 | α 两遍 KWS + 上下文决策 | β 小 footprint ASR + 语法解码 | γ 嵌入检索（原型 / QbE） |
|---|---|---|---|
| 核心 | 流式出候选 → 偏置复核 → 三态决策 | 粤语小型 CTC ASR → FST 匹配命令模板 | 瓶颈嵌入 + 每命令原型集 + 开集拒识 |
| 开放词表 | 需重训（模板通道补） | 天然开放 | 录 3 条即可 |
| 拒识能力 | 强（风险-覆盖 + 状态先验） | 强（LM 分数 + OOV） | 中-强（dummy 原型） |
| 数据需求 | 中 | **高**（无真人微调则 CER 崩） | 低-中 |
| Pi 实时性 | 好 | 风险高 | 好 |
| 课程风险 | **低** | 高 | 中 |
| 文献支撑 | U2-KWS、MLPerf Tiny | Small-footprint open-vocab KWS | Prototypical / DONUT / Rusci |

**选型**：主线 **α**；把 **γ 的嵌入层作为 α 的共享表征**（同一个瓶颈同时服务命令头、
原型检索、说话人头）；**β 降级为未来工作**，但其 pass-1 的 CTC 实现方式保留为 α 的可选升级。

## 6. 核心机制设计

### 6.1 机制 1：两遍识别（Pass-1 候选 + Pass-2 偏置复核）

- **Pass-1**：1 s 窗、100 ms 步进的滑窗打分（复用现有 CNN 集成），
  或升级为 CTC 帧级解码（需训练框架支持，见 §11 风险 R-3）。
  输出候选命令与累积证据；命中即触发**预触发反馈**（OLED 亮起 / 短提示音），**不执行动作**。
- **Pass-2**：对 Pass-1 切出的片段做整句推理，叠加**关键词偏置**
  （把候选命令的先验加到 logit 上，等价于 U2-KWS 的 keyword bias 的简化版）。
  输出：后验、3 种子集成方差、top-2 margin。
- **一致性规则**：两遍一致 → 进入决策层；不一致 → 强制降级为黄区或红区。
- **理由**：Pass-1 拿到流式延迟收益，Pass-2 保住整句准确率；复核成本约 10 ms，可忽略。

### 6.2 机制 2：风险-覆盖拒识（取代单点阈值）

- 采用 Geifman & El-Yaniv 的选择性分类框架：
  给定目标风险 `r*`（如高风险命令 0.02、普通命令 0.08），
  在校准集上搜索选择函数阈值 `θ`，使经验选择性风险 ≤ `r*`，
  并用有限样本修正（Hoeffding / PAC-Bayes 型界）给出高概率保证。
- **校准集**：验证集（按表达组划分）+ 合成未知指令 + **真人粤语非命令语音**（新增，见 §7.2）。
- **报告**：完整风险-覆盖曲线、AURC、ECE，而非单点。
- **注意**：保证成立的前提是校准集与部署分布可交换；分布漂移时上界失效，需定期重标定并如实标注。
- **实测依据（S0，2026-10-31）**：单一 max-prob 阈值在真人语音上已饱和失效——覆盖率在
  FAR 0.15 → 0.10 之间断崖（0.6159 → 0.0023），抬阈值无法同时满足 FAR 与可用性，
  本机制由设计动机变为实测必需（详见 §9.1 结论）。
- **实现与实测（S3，2026-11-01，详见 §9.2）**：`src/selective.py` + `scripts/eval_selective.py` 已交付。
  最强工作点是 **maxprob ≥ 0.3092 AND ood ≥ −0.0202**（ood = 嵌入 kNN 余弦距离取负），
  真实域 FAR 0.3110 → **0.0660**、危险误动作率 0.1437 → **0.0201**、合成覆盖率 0.7864 → **0.8455**。
  该信号同域 AUC 0.9384 ≥ 跨域 0.9244，判定为内容判别器而非 TTS/真人域检测器，这是结论可用的前提。
- **与本节原设计的一处偏离（S3 首测时有意为之，随后已被复核推翻）**：原计划把真人非命令语音
  放进校准集；S3 首测**只在合成侧拟合**阈值，真人集仅用于评估，理由是唯一那批真人数据同时是
  唯一的评估集，拿它选阈值就没有独立报告可言。§9.2 用 oracle 验证了这个选择的代价为零
  （oracle 落在完全相同的阈值与覆盖率上）。
- **但合成侧标定这条流程本身不可复现（2026-11-01 追加实测）**：固定参照池、只对那 72 条
  合成负样本做有放回重采样，真实域 FAR 在 **[0.0660, 0.1998]**（p10–p90，200 次）之间摆动，
  最坏 0.2954，产生 6 组不同阈值——跨度已超过目标 FAR。上条那个「代价为零」是**这一次抽样**
  的结果，不是流程的性质。
- **修正后的标定口径（本节设计的正式版本）**：按上面预告的「交叉验证式划分」实现
  `runtime/selective.crossfit_and_rule`——真人负样本做 2 折 × 3 次随机划分，每折阈值只用
  其余折搜出，只在本折评估。6 个折全部选中同一工作点 `maxprob ≥ 0.309193 AND ood ≥ −0.020189`，
  合并样本外 FAR **0.0660**（min = max），覆盖率 **0.8455**。这样既把标定集扩到数千条，
  又保住了独立性（每条样本都由没见过它的阈值判定），所以报出的 FAR 是无偏的样本外估计，
  既不是 oracle 也不是自欺。**代价**：真人负样本参与了标定，「本项目完全不需要真人数据」
  的说法在标定环节不再成立，对外表述必须改掉。
- **下发版本（S4，2026-11-01，详见 §9.3）**：端侧放不下满池（1981 条 f32 ≈ 2.03 MB），
  实测后定为 **500 条分层子采样 + f16**（落盘 275.9 KB），并按这份池**重新标定**：
  `maxprob ≥ 0.309193 AND ood ≥ −0.022306`（k=5），交叉拟合样本外 FAR **0.0812**、
  合成覆盖率 **0.8205**。阈值与池是**一对**工件，`SelectiveGate.load` 在池条数与规则不符时
  硬失败；f16 往返发生在标定**之前**，理由与上一条相同——标定必须落在实际下发的那份数值上。
  类质心方案（6–96 条）实测全部不达标，已排除。
- **仍未做**：有限样本修正（Hoeffding / PAC-Bayes 界）。交叉拟合给出的是无偏**点估计**，
  不是高概率上界；当前只报 Wilson 95% CI（且仅在所有折选中同一阈值时有效）。

### 6.3 机制 3：设备状态先验 + 期望代价三态决策

- **状态先验**：`P(c | audio, state) ∝ P(audio | c) · P(c | state)^τ`，`τ` 为先验温度（默认弱先验，如 0.3）。
  例：窗帘当前为「开」→ `P(CURTAIN_CLOSE | state)` 提高。
- **护栏**：先验**只在黄区生效**；当声学证据与先验强烈冲突（margin 大且方向相反）时不覆盖声学结论。
  必须有反例测试（先验错误时系统不得执行错误动作）。
- **代价决策**：定义三类代价 `C_act_wrong`（误动作，按命令风险分级）、`C_reject`（拒识，用户重说成本）、
  `C_clarify`（澄清，打扰成本）。三态阈值由期望代价最小化解出，而非人工拍定。
- **状态源**：Home Assistant REST / MQTT；无 HA 时用 mock 状态机（演示与测试均可离线跑通）。

### 6.4 机制 4：端侧末层适配（个性化最小版）

- **采集**：校准模式引导用户说 6 命令 × 3 遍 + 30 s 环境噪声，约 1 分钟。
- **更新范围**：仅 CMVN 统计量 + 最后一层偏置（或 1×1 线性适配器），纯 numpy，秒级完成。
  依据：arXiv 2505.09304 表明只调末层即可在低 SNR 下取得大幅增益。
- **护栏**：留出部分校准样本做验证，**只有指标提升才启用**；适配器版本化，一键回滚；
  任何情况下不改动骨干权重。

### 6.5 机制 5：动作优先 + ACK 闭环 + 去抖

- 复核通过后**立即**下发执行指令（目标：语音结束 → 动作 P95 ≤ 300 ms），同时给短提示音。
- 普通话播报**异步**进行，不阻塞动作。
- 执行器回报 ACK 后再播「已完成」；超时/失败播错误提示（现为开环播报，可能「说做了但没做」）。
- **去抖**：同一命令 2 s 内抑制重复执行，防止流式连发。

### 6.6 机制 6：共享瓶颈多任务表征

- 单一骨干输出瓶颈嵌入，接三个头：命令帧后验、说话人、噪声/场景。
- 一份模型同时服务：命令识别、声纹门控（延伸）、噪声自适应、原型扩展（γ 通道）。
- 依据：PCOV-KWS 的多任务统一路线；避免 v4 中「流式模型 + 是/否模型 + 模板匹配」三套模型各自为政。

### 6.7 交互：澄清策略

- 黄区且 top-2 命中**已知易混对**（当前：CURTAIN_OPEN ↔ CURTAIN_CLOSE，占误判 32.8%）时触发。
- 形式：普通话问句 + OLED 高亮两个候选 → **请用户重说一次** → 重新走完整决策链。
- **最多澄清一次**；仍不确定则拒识并播报可用命令。
- 不自研是/否识别模型（v4.1 已砍）：用户重说时天然更清楚，且复用同一条链路。

```yaml
risk:
  target_far_default: 0.08
  target_far_by_command: {CURTAIN_OPEN: 0.05, CURTAIN_CLOSE: 0.05, ALL_OFF: 0.10}
  finite_sample_confidence: 0.99
decision:

  cost_act_wrong: 10.0
  cost_reject: 4.0        # 草稿写 1.0，实测下澄清永远触发不了，见下方说明
  cost_clarify: 1.5
  competitor_floor: 0.005
  prior_override_margin: 0.15
  consistency_margin: 0.15 # 两遍不一致时的降级门槛
  redundancy_weight: 0.25
  confusable_pairs: [[CURTAIN_OPEN, CURTAIN_CLOSE]]
  debounce_ms: 2000
  max_clarify: 1
streaming:
  pretrigger: true
  window_ms: 1000
  hop_ms: 100
  pretrigger_threshold: 0.5
  fast_endpoint_threshold: 0.5   # 快速端点门槛，与严格预触发解耦
  fast_silence_ms: 120
  keyword_bias: 0.3
adaptation:
  enabled: true
  update_scope: [cmvn, last_layer_bias]
  require_improvement: true
state_source: mock        # mock | home_assistant | mqtt
```

**已落地（S4(b), 2026-11-03）**：`streaming` 段按实际接线改写。三处与草稿不同，
每处都有实测依据，不是笔误：

- `cost_reject` 取 **4.0** 而不是草稿的 1.0。按 1.0 算期望代价，
  `E_clarify(1.6) > E_reject(1.0)`，澄清永远不是最优动作，澄清机制形同虚设。
  拒识意味着用户整句重说，比二选一澄清贵，所以拒识代价必须高于澄清。
- `fast_endpoint_threshold`（0.5）是从 `pretrigger_threshold` 里**拆出来的**：
  快速端点只要**一个窗**的后验过门槛就生效，严格预触发仍要**连续两窗**证据一致。
  两者解耦是 300 ms 预算能成立的前提（§9.4 第 2 点）。
- `fast_silence_ms`（120）是快速端点命中后的静音挂起；默认仍是 `vad.min_silence_ms`（400）。
  语料是按默认挂起切的，所以挂起压到 120 ms 会把「句中停顿超过 120 ms」的语音段切早，
  这是已知的硬取舍（R-14，§9.4 第 4 点），不是配置疏漏。

**已落地（S4, 2026-11-01）**：`recognition.selective` 段已写入 `config.yaml`，
门限与参照池是**一对**工件，换池必须重新标定阈值。

```yaml
    gate: runtime/models/v3_selective_gate.json    # 规则 + 阈值 + 标定元数据
    pool: null                                     # null = 由规则文件里的 ood.pool 决定
    fallback_mode: single                          # single | reject：拿不到嵌入/池时的退路
```

### 9.1 S0 实测结果（2026-10-31，真实域拒识首测）

**测试集**：2744 段 / 7807.8 s，来自 819 条真人粤语（FLEURS `yue_hant_hk` test，CC BY 4.0，见 §7.2）；
转写逐条核查 2744 条，命中命令短语 **0** 条，13 条提到器件词（如「燈塔」）属合法负样本未剔除；
唯一剔除是 20 条过短。实际评估 2637 段（107 段孤立重跑 VAD 判无语音）。

| 指标 | 数值 |
|---|---|
| 真实域 FAR（部署阈值 0.945） | **0.3110**，Wilson 95% CI [0.2936, 0.3289] |
| 合成 unknown FAR（n=72） | 0.125 → **域差距约 2.5 倍，置信区间不重叠** |
| 危险误动作率 | **0.1437**，CI [0.1309, 0.1576]，379 段 |
| 危险误动作分布 | ALL_OFF 212 / LIGHT_OFF 146 / LIGHT_ON 13 / CURTAIN_CLOSE 5 / CURTAIN_OPEN 3 |
| 无害查询 STATUS_ALL | 441 段（0.1672），已单列，不计入危险误动作 |
| 真人负样本置信度分位数 | p50 0.8496 / p90 0.9923 / p95 0.9971 / p99 0.9996 / max 1.0000 |
| 跨域 AURC | 0.1828（20 档；覆盖率为合成侧，非标准 AURC，见 §12 第 8 项） |

**阈值反解**（真实域 FAR 目标 → 所需阈值 → 合成验证集覆盖率）：

| FAR 目标 | 所需阈值 | 合成覆盖率 |
|---|---|---|
| 0.15 | 0.9847 | 0.6159 |
| 0.10 | 0.9924 | **0.0023** |
| 0.08 | 0.9944 | 0.0023 |
| 0.05 | 0.9971 | 0.0023 |
| 0.02 | 0.9992 | 0.0023 |

当前部署阈值 0.945 的合成覆盖率为 0.7773。

> **最重要结论**：覆盖率在 FAR 0.15 → 0.10 之间断崖（0.6159 → 0.0023），说明
> **单一 max-prob 阈值在真人语音上已经饱和失效**——约 10% 的真人非命令语音拿到
> ≥ 0.9923 的置信度，模型对域外输入是「高置信度地错」。降 FAR 不能靠继续抬阈值
> （抬到能达标时产品已经不可用），必须引入第二信号（集成方差 / margin）与
> 风险-覆盖框架，即 **S3 必须提前，优先级高于 S1/S2**（见 §10、§11 R-11）。
> 这与 §6.2 的设计动机一致，现在有了实测依据。
>
> **口径限制**（详见 §12 第 7、8 项）：FLEURS 是朗读式、相对干净、近讲的真人粤语，
> 0.3110 对应「干净朗读粤语被 VAD 切成命令长度片段」的条件，真实家庭环境大概率更差，
> 该值**不是保守上界**；覆盖率一侧为合成验证集，是真人命令覆盖率的乐观代理。

**标定可靠性复核（2026-11-01 追加，`scripts/eval_pool_size.py` + `runtime/selective.crossfit_and_rule`）**

上表那个 0.0660 的**产生过程**并不稳，必须与它的**数值**分开评价：

1. **对照实验（标定噪声底）**：池完全不变，只对那 72 条合成负样本做有放回重采样（200 次），
   每次重新搜阈值再到真人集上评估——真实域 FAR 在 **[0.0660, 0.1998]**（p10–p90）之间摆动，
   最坏抽样到 0.2954，共产生 **6 组**不同阈值。跨度已超过 0.10 的目标 FAR，
   所以「72 条合成负样本上搜出的点估计」本身不构成可复现保证；**瓶颈是标定集大小，不是信号选择**。
2. **交叉拟合复核（可部署规则的样本外估计）**：把标定集换成 2637 条真人负样本，做
   2 折 × 3 次随机划分——每折阈值只用其余折搜出，只在本折上评估。
   **6 个折全部选中同一对工作点** `maxprob ≥ 0.309193 AND ood ≥ −0.020189`
   （`n_distinct_thresholds = 1`），三次划分的合并样本外 FAR 均为 **0.0660**（min = max），
   覆盖率 **0.8455**。
3. **因此结论修正为**：规则本身站得住（0.0660 通过了样本外验证，且工作点在数千条负样本上唯一），
   但「只用 72 条合成负样本标定」这条**流程**这次是撞对了答案，不能作为可复现的标定方案沿用。
   代价是：交叉拟合让真人负样本参与了阈值搜索，§9.2 原来那句「没有真人负样本也没有可测损失」
   只在 oracle 与本复核都选中同一工作点的意义上成立，**「本项目完全不需要真人数据」的说法在标定环节不再成立**。
   实际下发时阈值会用全部真人负样本一次性拟合——oracle 一栏显示这与交叉拟合选出的工作点相同。

1. 覆盖率一侧全是合成 TTS。`ood` 门限量的是「到合成 train 嵌入池的距离」，

   真人命令覆盖率在有真人正样本前无法测（见 §12 第 7 项）。
2. ~~kNN 参照池 1981×256 float32 ≈ **2.03 MB**，比模型本体（1.35 MB）还大。

   分层子采样 500 条、存 f16，落盘 275.9 KB，样本外 FAR 0.0812、覆盖率 0.8205，
   仍满足判据；类质心方案实测不可行（覆盖率 0.5386–0.7932，无一达标）。
3. `maxprob+seed_agree` 明显更弱（FAR 0.2139）；集成分歧单独有用（AUC 0.9054）

4. ~~该规则**尚未接入** `src/realtime.py` 的实时决策路径，属 S4 范围~~ ——

#### 2. 快速端点必须与严格预触发解耦（软候选）

**问题**：快速端点原本挂在严格预触发上（连续两窗证据一致）。但 Pass-1 的窗长是 1 s、

结构上永远等不到预触发，挂起压在默认 390 ms，动作延迟 P95 落在 **374 ms**，300 ms 预算破掉。

**做法**：把门槛拆成两个。

| 通路 | 门槛 | 用途 | 命中后 |

| 软候选 | 单窗后验 ≥ `fast_endpoint_threshold`（0.5） | **内部的时序决策**，不等两窗 | 只压挂起，不记候选、不加关键词偏置 |

`DialectVoice_Research/src/streaming.py`，由 `scripts/sync_runtime.py` 生成）、
`src/realtime.py::process_stream_block` 的 `elif detector.soft_candidate is not None` 分支、

| stream（部署路径） | 0.7097 | 0.6968 | 0.6968 | 0.1097 | **0.0000** |

S5 §10 写的验收目标是「**易混对任务成功率提升**」。这个目标在部署口径下增益为 **0.0000**，
**未达成**；offline 口径下有 +0.0709，但 offline 没有 Pass-1 候选、没有关键词偏置、
没有两遍一致性，**走的不是线上代码**，不能拿来交差。

部署路径更差的三个原因（逐条都有工件支撑）：

1. **输入被截断**（见本节第 4 点）：部署路径的 argmax 准确率比 offline 低 0.0331。
2. **关键词偏置把错误候选锁死**：33 条错误执行里 28 条被判为 `consistent`
   （Pass-1 候选 == Pass-2 top-1）——偏置让 Pass-2 认同了错误候选，一致性规则于是放行。
3. **一致性规则太严**：483 条里 161 条（33.3%）是 `inconsistent`，其中 **148 条的
   Pass-2 argmax 本来是对的**，只因 Pass-1 候选不同而被降级（`consistency_margin=0.15`
   的门控只拦下 22 条）。

#### 4. 已知缺陷：快速端点会把话切早（训练/部署不一致）

训练语料是用**默认静音挂起**切的（`scripts/make_trimmed_corpus.py`，400 ms → 13 帧 =
390 ms），模型没见过「句中被截断」的输入。部署路径的快速端点把挂起压到 120 ms，
句内只要有超过 120 ms 的停顿就会**提前切段**，后半句被丢给下一段。

| 指标 | 数值 |
|---|---:|
| 对比样本数 | 480 |
| 被提前切段 | **18**（0.0375） |
| 被切成多段 | 32 |
| 提前切段后仍执行 | 8 |
| 其中执行了**错误命令** | **8**（错误率 1.0000） |
| 错误流向 | 全部是 CURTAIN_OPEN → CURTAIN_CLOSE |
| 未截断样本的错误执行率（对照） | 25/371 = 0.0674 |

**这是硬取舍，不是阈值问题**：把挂起恢复到 390 ms 可以消除截断，但动作延迟回到
约 400 ms，300 ms 预算与「不切早」在这份语料上**互斥**。可选解法（属 S5 级别）：

- **合并重判**：切早时先不执行，等下一段接上后合并成完整一句再复核（需要 VAD 支持
  「延迟提交」而不是立即切段）；
- **按部署端点重建语料**：用与部署一致的快速端点切训练语料，让模型见过被截断的输入
  （代价是训练集分布随挂起参数变化，必须与部署参数一起版本化）；
- **提高快速端点门槛**（`fast_endpoint_threshold`）：少切早，但弱样本会更慢。

#### 5. 限制

1. 全部数字来自**合成 TTS 语料**，真人命令正样本仍为 0，**不得当作真人性能**。
2. 预触发音频口径按构造 ≥ 1.1 s，**不能**与 150 ms 的目标比；150 ms 只对 CPU 口径成立。
3. 延迟为离线 CPU 测量，目标硬件（树莓派）上的真实值待实测。
4. 会话级评估的重说样本取自同一命令的**另一个表达组**——这个假设偏乐观
   （同一表达组兄弟样本准确率只有 0.358）；`--retry-mode same` 是悲观对照口径。
5. `dialog_eval.json`（offline）与 `dialog_eval_stream.json`（stream）的 argmax 口径
   都用**无偏**后验，可比；`single_gate`（同样带门限、无对话补救）与 `dialog` 之间可比。

3. **训练侧能力**：现有 Research 训练脚本是否支持 CTC、多任务头、量化导出。
4. **算力**：多说话人 TTS 是否需要 GPU；本机可用算力上限。
5. **硬件**：HA/MQTT、OLED、麦克风阵列在课程环境中的可得性。
6. **文献细节**：本文引用的数字（如 +41%、46%、99.4%）来自检索摘要与论文页面，
   实施前需回到原文核对上下文与实验条件，不得直接搬进对外材料。
7. **FLEURS 域代表性（S0 新增限制，未验证）**：FLEURS 是**朗读式、相对干净、近讲**的
   真人粤语（维基句子），不是家庭远场噪声环境；且句子长 5–20 s，被 VAD 的
   `max_utterance_ms: 4000` 切成命令长度的片段。因此 FAR 0.3110 对应的条件是
   「干净朗读粤语被切成命令长度片段」，真实家庭环境（远场、电视背景声、多人）
   大概率更差，不会更好。**0.3110 不是保守上界**，报告中不得这样引用。
8. **覆盖率口径（S0 新增限制）**：阈值反解中覆盖率一侧用的是**合成**验证集，
   是真人命令覆盖率的乐观代理；真实域 FAR 与合成覆盖率的组合曲线不是标准 AURC。
9. **真人命令在 OOD 门限下的存活率（S3 新增，未验证，对应 R-12）**：`ood` 信号量的是
   到**合成 train 嵌入池**的余弦距离。已验证的是真人**非命令**语音离池远（这正是 FAR 下降的来源），
   **未验证**的是真人**命令**语音是否也离池远——若是，覆盖率（满池 0.8455、
   下发的 500 条池 0.8205）在真人身上会大幅缩水，FAR 收益被误拒代价抵消。
   没有真人命令正样本就无法测，采集到位后这是第一件要做的事；届时必须用**下发的那份
   500 条 f16 池**重测，而不是满池。
10. **kNN 参照池的下发方式（S3 新增，对应 R-13）——已实测决定，2026-11-01**：
    分层子采样 500 条、存 f16，落盘 275.9 KB / 内存 500 KB，样本外 FAR 0.0812、
    覆盖率 0.8205，满足判据；类质心方案实测不可行（详见 §9.3）。
    **仍未验证**的是这个结论对**真人命令**是否成立——池压缩掉的 1481 条全是合成嵌入，
    真人命令语音到 500 条子池的距离分布未测（与第 9 项同一个缺口）。
11. **有限样本高概率保证（S3 未做，方差已实测）**：§6.2 计划的 Hoeffding / PAC-Bayes
    修正仍未实现，当前只报 Wilson 95% CI，不构成选择性分类意义上的风险上界保证。
    但「72 条同域负样本上的 risk 估计方差很大」已从推测变成实测：固定池、只重采样标定集，
    真实域 FAR 的 p10–p90 为 **[0.0660, 0.1998]**（200 次，6 组不同阈值，见 §9.2 复核）。

    降级过严，但具体阈值没有现成解，需在 `docs/dialog_eval_stream.json` 上网格搜。
14. **300 ms 预算的普适性（S4(b) 新增）**：P95 = 142.7 ms 达标，但 379 条执行样本里
    仍有 5 条保留默认 390 ms 挂起（既没命中软候选也没命中严格预触发），动作延迟约
    400–404 ms。**未验证**的是软候选门槛 `fast_endpoint_threshold` 调到多少能在不显著
    拉高截断率的前提下把这类样本也压进预算——抬高门槛会减少挂起压缩的触发面，
    降门槛会增加切早，二者必须一起量，不能分开调。

## 13. 明确不做

- 云端 ASR / LLM 意图解析（违背 R2 离线目标）
- 端侧大模型运行时（仅允许离线做教师 / 标注）
- 自研唤醒词（改用 openWakeWord / microWakeWord）
- 自研是/否识别模型（改为请用户重说）
- 从零训练流式 CTC（Pass-1 优先滑窗判别式）
- 槽位化命令语法（超出 6 命令范围，写入未来工作）
- 多模态摄像头融合
- QbE 模板扩展的完整实装（只留接口与文档）
