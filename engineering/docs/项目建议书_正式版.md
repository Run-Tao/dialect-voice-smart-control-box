# 项目建议书

## 基于方言语音识别的智能家居语音转换装置

项目类型：本科工程导论项目  
周期：约2个月  
预算：1000元以内  
前期基础：MFCC 特征、DTW 模板匹配、判别式建模、CNN 推理与拒识  
预期成果：可现场演示的方言语音智能家居控制原型  

> 2026-10-30 修订说明：本文技术路线已根据项目自有实验结果调整，
> 原「方言→普通话特征映射」主线因下游识别准确率等于随机水平而取消，
> 改为「端侧直接分类 + 拒识 + 语义层播报」。修订依据见
> `docs/技术路线修订说明.md`。

# 一、项目背景与意义

很多老年人习惯说方言，而主流智能家居设备主要面向普通话。方言口音会导致识别率下降，
老人使用门槛较高。现有智能音箱多为封闭系统，普通开发者很难修改固件或直接接入厂商语音接口。

本项目做一个智能家居语音转换装置：用户说方言，装置在端侧完成识别与置信度判断，
再以标准普通话指令播报给智能音箱执行；同时保留串口/继电器直控通道作为备用方案。
该方案不改音箱固件，不依赖厂商API，成本低，便于演示。

# 二、前期基础与工程转化

前期已完成的研究工作包括：

- 方言与普通话家居指令语料库与合成语料生成流水线；
- MFCC/log-mel 特征提取与整句 CMVN 归一化；
- DTW 模板匹配、OLS/Ridge 回归映射、Softmax 回归、线性 SVM、1D-CNN 等多条路线；
- 置信度拒识与阈值标定；
- 串口协议、模拟设备、Web 演示台。

需要在本次工程化中补足的内容：

- **实时音频通路**：麦克风采集、VAD 端点检测、连续流式推理（此前仓库中完全没有实现）；
- **训练与部署同源**：此前模型在带尾部静音的整段音频上训练，与线上 VAD 输出分布不一致，
  已定位并通过「用部署同款 VAD 重生成语料再训练」修正；
- **语义层转换与执行**：命令标签到普通话指令的播报、智能音箱联动、串口/继电器备用通道；
- **真人数据**：现有全部性能数字均来自合成 TTS，必须补真人采集；
- **测试报告与成本核算**。

# 三、项目目标

- 支持 6 条固定家居命令：开灯、关灯、开窗帘、关窗帘、全部关闭、查询设备状态；
- 在低成本设备上完成方言语音的端侧实时识别，单条推理延迟实测 13–16 ms（特征提取 + 推理）；
- 置信度低于阈值时不执行动作，并提示重说；
- 通过扬声器播放标准普通话指令，与智能音箱联动；
- 通过 OLED 显示识别结果与置信度；
- 保留 ESP32-S3 串口控制与继电器直控作为演示备用；
- 完成真人数据采集、测试报告、成本核算与现场演示。

# 四、技术路线

总流程：

方言语音 → VAD 端点检测 → log-mel40 + Δ 特征（整句 CMVN）→ 1D-CNN 3 种子集成
→ 温度标定置信度 → 阈值拒识 → 语义层映射（命令标签 → 普通话指令）
→ 扬声器播放 / 串口下发 → 智能音箱或设备执行

- **数据**：合成语料 2904 条（六类，3 个粤语音色 + 多语速/音高条件 + 纠正否定句式），
  按「表达组」划分固定训练/验证/测试集，测试集 483 条为未见表达组；
- **前端**：16 kHz 单声道，VAD 采用帧能量 + 自适应噪声底 + 静音挂起，输出紧贴语音的音频段；
- **特征**：40 维 log-mel 及其一阶差分，整句 CMVN，线性插值到 256 帧；
- **模型**：1D-CNN，3 个随机种子集成，纯 numpy 推理，模型体积约 1.35 MB；
- **拒识**：温度标定后的最大概率作为置信度，阈值只在验证集与未知校准集上选取；
- **输出**：置信度达阈值才执行，否则提示重说；
- **语义层转换**：命令标签映射到普通话指令文本，预录为音频后播放给智能音箱。

## 关于取消「方言→普通话特征映射」的说明

前期方案曾以 MFCC + SVD + 回归映射作为主线。工程化阶段用自有实验核对后取消该主线：
在 30 组方言-普通话语义配对上，回归拟合的特征级指标很好（RMSE 0.025、余弦 0.999），
但映射后特征的命令识别准确率为 0.1667，与 6 类随机基线相同；而同一份数据上
端侧 CNN 的固定测试集准确率为 0.9048。原因是统一回归矩阵只约束特征空间整体形态，
未按命令类别条件化，类别判别边界在映射后被抹平。转换因此改到语义层进行。
完整依据见 `docs/技术路线修订说明.md`。

## 当前已完成的工程结果

部署模型 `v3_cnn_ensemble_vad.npz`（在部署同款 VAD 裁剪后的同源语料上重训练）+ 拒识阈值 0.945，
在 483 条未见表达组测试集上实测：

| 指标 | 数值 |
|---|---:|
| 命令识别准确率（argmax） | 0.8799 |
| 接受率 | 0.7598 |
| 接受样本准确率 | 0.9319 |
| 未知指令误接受率 | 0.125 |
| 单条推理延迟 | 13–16 ms |

修复前（旧模型直接接线上 VAD）的同一批实测为：argmax 0.7395、LIGHT_ON 0.1716、
未知指令误接受率 0.4444。同源重训把短命令从崩溃拉回可用区间，误接受率降到约 1/4。

需要如实说明：验证集准确率 0.9477、测试集 0.8799，差 6.8 个百分点，
弱点集中在窗帘类命令（CURTAIN_CLOSE 0.6849、CURTAIN_OPEN 0.7561），
说明当前窗帘类表达组多样性不足，第 3 周真人采集时需优先补这两类。

# 五、系统方案

硬件：

- 端侧推理主机：PC 或树莓派 4B/Zero 2W；
- USB 麦克风；
- 扬声器与功放（播放普通话指令）；
- ESP32-S3 + LED + SG90 舵机 + OLED（执行端，串口受控）；
- 演示用灯与窗帘模型；
- 电源、线材、外壳。

软件模块（全部本地运行，不联网）：

- `src/vad.py`：VAD 端点检测；
- `src/realtime.py`：实时管线（切段 → 特征 → 分类 → 拒识 → 执行 → 播报）；
- `runtime/`：自包含推理运行时（纯 numpy，含模型工件）；
- `src/control.py`：执行层（串口 ESP32-S3、模拟 ESP32、继电器、日志）；
- `src/speaker_out.py`：普通话指令播报；
- `src/ui.py`：OLED 与控制台显示。

联动方式：装置播放预录的普通话命令音频，智能音箱接收后执行；
若现场联动不稳定，改用串口 ESP32-S3 或继电器直接控制演示设备。

# 七、数据采集与实验

**合成语料（已完成）**：2904 条粤语合成语音，六类命令，覆盖短指令/口语/礼貌/疑问/纠正句式，
以及语速、音高条件变体；固定测试集为 483 条未见表达组。

**真人语料（待补）**：2–3 位方言使用者，每人每命令 30–50 次，
覆盖安静环境与电视/风扇噪声环境、近距离与 1–3 m 远距离；
另需采集不属于六类的未知指令作为拒识负样本。

**数据划分**：按表达组划分，避免同一表达的不同音色/条件变体跨集合泄漏。

**对比实验**：

1. MFCC+DTW 基线 vs log-mel+CNN；
2. VAD 前 / 后消融（验证端点检测对准确率与误接受率的影响）；
3. 安静/噪声、近/远距离、已注册/未注册用户。

**评价指标**：命令识别准确率、接受样本准确率、未知指令误接受率、
端到端延迟、智能音箱执行成功率、误触发率、总成本。
（不再使用「映射均方根误差」，因映射路线已取消。）

# 九、风险与应对

- **合成与真人的域差距**：现有全部数字来自合成 TTS。应对：第3周优先补真人语料，
  报告如实标注哪些数字是合成的、哪些是真人实测。
- **未知指令误接受**（当前最突出的安全短板）：合成集上实测 0.125。应对：补采未知/易混负样本，
  阈值仅在验证集与校准集上选取，硬负例单独统计误接受率；
  演示中明确展示「低置信度不执行」。
  说明：原业务目标「已知覆盖率 ≥ 0.85 且误接受率 ≤ 0.08」在现有数据上没有可行工作点
  （阈值 0.985 时覆盖降到 0.6545），已把约束放宽为覆盖率 ≥ 0.80、误接受率 ≤ 0.15，
  这一取舍记录在 `runtime/models/v3_thresholds_vad.json` 中，需靠补难负样本来真正改善。
- **智能音箱对播放音频识别不稳定**：应对：预录普通话指令音频，调整音量/距离/角度，
  准备 ESP32-S3 串口与继电器两条备用通道。
- **真人语料不足**：应对：固定 6 条命令，2–3 位使用者反复采集；
  必要时用个性化注册模板补充。
- **端侧实时性不足**：应对：优先树莓派 4B，模型已纯 numpy 推理且体积 1.35 MB。
- **现场演示失败**：应对：准备预录演示视频、备用音频与继电器演示。
