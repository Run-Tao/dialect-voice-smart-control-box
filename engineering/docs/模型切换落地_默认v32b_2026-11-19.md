# 识别准确率优化模型切换落地：默认切换到 v3.2b（2026-11-19）

## 结论先行

把已交付但未部署的纠错句式覆盖修复模型 `v3_cnn_ensemble_v32b.npz` **正式设为默认**，并连带完成 OOD 重标、配置切换、C 内核重导出、测试同步与全量回归。切换后：

- 冻结 test 483 条 argmax **0.8820 → 0.9110（+2.90 pp，错 57→43）**；val 440 条 0.9500→0.9523（无回归）。
- 双信号拒识在新模型上**不退化反改善**：真人负样本 FAR 0.0812 → **0.0702**，危险误动作率 0.0212→0.0326（略升，见残留），合成覆盖率 0.8205 持平。此前"换模型必须回退单阈值"的顾虑被实测排除。
- 全量测试 **347 passed**（切换前 347），端到端串口 4 passed，C 端侧 int8 内核 483 条与 numpy **482/483 一致**。

所有旧工件已备份，`config.yaml` 与测试断言同步更新，无回退风险。

## 1. 为什么这次能安全切换（此前未切的原因）

上一轮优化报告（§6）没有把新模型设为默认，唯一阻塞是：换模型后 256 维 embedding 空间漂移，旧 `v3_knn_pool.npz` + `v3_selective_gate.json` 这对"池+阈值"工件失配，只改 config 路径会让双信号拒识行为不可信。可选路径有两条：

- **临时回退**：`selective.enabled: false` 走单阈值 0.945（覆盖率 0.8250 / 精度 1.0 / FAR 0.1389），精度不丢但 FAR 比双信号差。
- **完整整合**：用新模型重算 raw → 重标门限 → 切 config → 重导 C 内核 → 全量回归。

本轮选择完整整合，理由：新模型的 OOD 信号本身很强（AUC 0.9264，全部信号中最强），重标后双信号 FAR 反而更低，没有必要牺牲 FAR 走回退路径。

## 4. 残留与需关注

1. **危险误动作率略升**：双信号门限下 ALL_OFF 类危险误接受率 0.0212→0.0326（FAR 总体下降但危险类占比上升，真负样本中 ALL_OFF 误接受 65 条）。config 已配置 `high_risk_min_ood.ALL_OFF=-0.014` 作为高风险二次门槛，需在实机阶段核对该门槛是否仍适配新 embedding 空间（本轮未改动该参数，属后续观察项）。
2. **交叉拟合等价工作点**：折间搜出两组阈值（maxprob 0.51863 / 0.30677，ood 相同），FAR 与覆盖率完全相同（0.0702/0.8205），是低概率平台上的等价解，非工作点不稳。测试断言已改为"众数==下发 且 各折指标一致"，不放宽安全性。构建脚本打印的"工作点不稳定"提示属保守警告。
3. **剩余 43 个错误中 32 个仍是三条纯镜像纠错句**：在"测试句不进训练"约束下无解，除非重划分并重报所有历史数字（牵动另一 agent 工件），本轮不做。
4. **全部数字仍是 edge-tts 合成粤语**：真人命令正样本 0 条，提升的是合成测试集准确率，不等于真实场景准确率（R-14）。
5. **硬件实机未测**：C 内核耗时为主机 gcc 口径；ESP32-S3 上板耗时、GPIO/舵机/麦克风电气联调由硬件负责人负责。
