## 两条必须写清楚的限制

1. **识别准确率全是合成 TTS**。测试集是同音色、未见表达的 33 个文本，不是真人、不是跨说话人；真人命令识别率目前没有数据。
2. **真实域 FAR 是「真人非命令被误接受」**，只说明安全性的一半，不能写成真人命令识别率；覆盖率 0.8205 是合成侧代理。

## 不要写进正文的旧结论（容易被问倒）

- **「方言→普通话特征映射」主线**：特征级 RMSE 0.025、余弦 0.999，但映射后命令识别 0.1667，等于六类随机，已否决。只可作为「为什么改走语义层」的对照。
- 旧模型/旧阈值：`v3_cnn_ensemble_vad`、argmax 0.8799、阈值 0.309193 / -0.022306、树莓派主控预算、142.7 ms 的旧延迟口径，都只在讲演进时当历史对照，并标注旧口径。
- 二期「扩充数据不提升」是真实的负结果：可以作为研究现状/前期基础，说明「不再堆数据，转去做模型与拒识」的原因。
- 远程仓库的 `pc-dialect-engine`、`esp32-dialect-voice` 是两个独立尝试分支，不算本项目主线，不要混进正文。
- 不要把 `szpi/` 的板载路线写成已完成：目前只有 BSP 和硬件自检编译通过，录音/上传/UI/后端都还没实现。

## 还缺什么（按实际状态写待完成）

1. 真人命令采集：0 条；`engineering/scripts/collect_human.py` 已备，等人录。
2. 硬件实机联调：串口 / GPIO / 舵机 / 麦克风未接；`szpi/` 板卡也还没上真板。
3. 3 分钟演示视频、采购成本表、部分答辩材料。
4. 端侧是否上 S3 没定：C 内核主机约 107 ms/条，S3 估 0.5–1 s，可能超 300 ms 预算。
5. 快速端点切早（13/480）和三条纯镜像纠错句（剩余 43 错中 32 条）尚未根治。
