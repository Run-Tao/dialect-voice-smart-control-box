### 1.2 审查发现的缺陷（均已处理或明确说明）

1. **DTW 双向截断**：`max_frames=60` 对 query 与 template 同时截断，
   而语料最长 4.64s≈462 帧（10ms 帧移）。本轮把 `max_frames` 作为
   **验证集选择的超参**做扫描（实验 F），未擅自改动主链路配置。
2. **清单字段不足**：缺表达组ID、引擎、音色身份、语速/音高、条件类型、
   质量状态、批次、声道数、内容哈希 → 已扩展 13 个字段，旧清单缺列时读为空串。
3. **旧近重复审计存在方法学伪影**：`scripts/data_quality_audit.py` 用
   「MFCC 逐维均值+std 拼接向量」的余弦判重。因特征已做 CMVN，
   该向量几乎与文本无关地同向，导致大量 `cosine≈1.0` 的假「近重复」（约 210 对）。
   本轮改为「帧能量包络余弦」并区分**组内/组间**两类比较。
4. **历史"文本组划分"并不存在**：`src/split.py` 只按 `speaker_id` 分组；
   历史「表达留出」是按 `expression_type` 切分，与音色无关。
   因此**同一文本在不同音色下同时进入训练与测试**，存在文本级泄漏。
   → 历史 0.625 / 0.433 只能视为「已见音色+已见表达」条件下的历史基准。
5. **`scripts/train_dtw_control_model.py` 会覆盖演示模型** `data/models/*.pkl`。
   → 本轮实验全部写入 `outputs/v2_experiments/`，**未触碰** `data/models/`。
6. **canto-tts 只有单一音色**：安装包 `canto_tts==0.1.4` 的 ONNX 后端源码注释明确
   "Single baked default voice, no runtime voice cloning"，`ref_audio` 仅 torch 后端支持
   （torch 未安装），`control`/`tokens` 在 ONNX 后端直接 `raise NotImplementedError`。
   → 独立粤语音色实际只有 **4 个**。
7. **项目无 git**（`docs/project_audit.md` 已记录确认），无提交级追溯。
   本轮改用「清单哈希 + 划分哈希 + 参数快照 + 运行命令」保证可复现。

### 2.3 数量分配与一个必须报告的约束

原粤语 120 条（六类各 20 条）。目标 600 条、每类 100 条 ⇒ 每类缺 80 条，共 **480 条**。

每类只有 29 个表达组，80 条额度只能给出约 2.76 个变体/组。刻意选择：

```
每类 80 条 = 音色1×29组 + 音色2×29组 + 音色3×22组
```

即**额度全部用于建立音色覆盖**，语速/音高/canto 重复采样变体在本轮额度下未生成。

> 但实测发现 edge-tts 对相同 (文本, 音色, rate) 是**确定性输出**，
> 表达库中与 v1 同文本的 30 个组（每类 5 个：direct/colloquial/polite/question/correction
> 规范化后同文本）若用基准语速重生成，会产出与 v1 逐字节相同的文件
> （首次构建检出 54 条 sha256 冲突）。因此这 90 个槽位自动改用语速 **−12%**，
> 既消除重复，又正好补上任务要求的「同一文本的语速变化」维度。
> 最终 condition 分布：`legacy 120` / `text_morphology 390` / `rate_slow 90`。

### 3.2 质量检查

逐条检查采样率、声道、时长、RMS、峰值、静音比例、削波比例、有效语音帧占比。
规则：明显无效（空/非16k/非单声道/<0.35s/>12s/RMS<0.002/全零）→ `excluded`；
可疑（0.35–0.5s、静音>90%、削波>1%、语音帧<15%）→ `flagged`（保留并记录原因）；
其余 `ok`。**本轮 600 条全部为 `ok`，0 excluded，0 flagged。**

| 规范化文本跨子集重叠（train-test / train-val） | **0 / 0** |

**重要处理**：v1 组 ID 形如 `LIGHT_ON_short_direct`，v2 形如 `LIGHT_ON_01`，
两者文本可能完全相同。若不合并，同一文本会以两个组 ID 分别进入训练与测试

`canonicalize_expression_groups()`：按 `(command, 规范化文本)` 强制归入同一组，
**合并 30 个文本键、影响 120 行**，合并后泄漏归零。

### 3.5 轨道 B（未见音色）的可行性判定

只有 3 个 edge 音色可做留一。**关键限制**：由于语料是 3 音色 × 全部 29 个表达组，
留出任一首色后，**所有表达组仍在其余两音色中出现在训练集**，
因此**无法构造「音色未见 + 文本也未见」的严格子集**（实测各音色 strict 子集 n=0）。
轨道 B 因此只能验证「音色外推」，不能同时验证文本外推。

**判定：扩充数据前后差异不显著，点估计甚至是下降。不能声称性能提升。**

|---|---:|---:|---:|
| LIGHT_ON | 0.6341 | 0.5366 | −0.0975 |

## 五、错误分析 [已执行]

扩充后模型在固定测试集（111 条）上的混淆矩阵（行=真实，列=预测，
顺序 LIGHT_ON, LIGHT_OFF, CURTAIN_OPEN, CURTAIN_CLOSE, ALL_OFF, STATUS_ALL）：

```
 11  10   0   0   0   0     <- LIGHT_ON
  6   7   0   1   0   0     <- LIGHT_OFF
  0   0   6  16   0   0     <- CURTAIN_OPEN
  0   0   8   5   0   0     <- CURTAIN_CLOSE
  1   0   0   1  21   0     <- ALL_OFF
  2   2   2   0   1  11     <- STATUS_ALL
```

主要错误对（共 50 个错误）：

| 真实 → 预测 | 次数 | 占比 |
|---|---:|---:|
| CURTAIN_OPEN → CURTAIN_CLOSE | 16 | 32% |
| LIGHT_ON → LIGHT_OFF | 10 | 20% |
| CURTAIN_CLOSE → CURTAIN_OPEN | 8 | 16% |
| LIGHT_OFF → LIGHT_ON | 6 | 12% |
| STATUS_ALL → LIGHT_ON / LIGHT_OFF / CURTAIN_OPEN | 2 / 2 / 2 | 12% |
| 其余（ALL_OFF、CURTAIN_CLOSE 等） | 5 | 10% |

**40/50 = 80% 的错误是语义对立意图对**（开↔关、拉埋↔打開）。
声学审计独立佐证了这一点：跨不同意图的最高能量包络余弦正是
`CURTAIN_CLOSE_13`（可唔可以幫我拉埋窗簾）vs `CURTAIN_OPEN_13`
（可唔可以幫我打開窗簾）= **0.9882**，两句只差一个动词。

**结论：瓶颈是"方向词"的区分，而不是数据量。**
MFCC+DTW 在整句层面比较，单个音节的声母/韵母差异被 60 帧的整体能量结构淹没。

## 六、拒识机制检查 [已执行]

阈值**只在验证集**选择（并配合未参与最终评估的未知文本校准组），
测试集只用于最终评估。未知命令样本共 24 条合成 TTS（8 个文本 × 3 音色），
按文本对半分为校准 12 条 / 测试 12 条。

选定阈值 **0.62**。测试集结果：

| 指标 | 值 |
|---|---:|
| 已知命令覆盖率 | 0.5225 |
| 已知命令误拒识率 | **0.4775** |
| 被接受样本准确率 | 0.5862（无阈值时 0.5495） |
| 未知命令误接受率 | 0.0（12 条中 0 条被接受） |
| 未知命令拒识率 | 1.0 |

**解读与限制（必须同时读）**
- 提高阈值确实把"接受样本准确率"从 0.5495 提到 0.5862，但代价是**拒掉 47.8% 的合法命令**。
- 未知误接受率 0% 建立在**仅 12 条未知样本**上。按 rule-of-three，
  真实误接受率 95% 置信上界约为 **3/12 = 25%**。因此**不能**把 0% 解释为"系统已有可靠安全性"。
- 未知样本与已知命令同源（相同 3 个 TTS 音色、部分共享粤语词汇），
  不能外推到真人语音或任意未登记命令。

## 八、结论：准确率是否真正提升

### 已实际执行并验证
- 粤语语料从 120 条扩充到 **600 条**，六类各 100 条，0 条排除，0 条重复。
- 建立**无泄漏固定测试集**（111 条 / 31 个表达组），泄漏检查全部为 0，
  划分文件哈希固定 `b9b42403525e80b9…`。
- 完成 E1/E2/E3/E4/B/N/F 七组实验 + 拒识评估 + v1-vs-扩充配对检验。

### 核心结论（负结果，必须如实报告）
1. **扩充数据没有带来可重复的准确率提升。**
   固定测试集上 v1 基线 0.5766 / 0.5632，扩充后 0.5495 / 0.5411；
   差值 −0.027，95%CI [−0.194, +0.111]，McNemar p=0.736 ⇒ 属噪声。
2. **数据规模不是瓶颈**：86→397 条训练样本，测试准确率 0.55–0.59 无单调上升。
3. **模板数与模板策略也不是可靠杠杆**：验证集选中 `all`；`medoid` 未显著优于 `all`；
   各策略置信区间全部重叠。
4. **真正的瓶颈是语义对立意图对的方向性混淆**：80% 的错误发生在
   开↔关灯、开↔关窗帘之间；声学审计显示对立表达的能量包络余弦高达 0.988。
5. 历史 0.625（表达留出）/ 0.433（音色隔离）**不能与本轮结果并列比较**：
   它们存在文本级泄漏，且严格测试集仅 6 条。本轮已把它们降级为历史参考。

### 不确定性
- 测试集 111 条 / 31 个表达组，自助法 95%CI 宽度约 ±0.15，
  只能识别中等以上效应；本轮的 −0.027 远小于该宽度。
- 验证集仅 92 条，验证集选择本身不稳定（E3 的验证集排序与测试集排序不一致）。
- 全部结论仅适用于**合成 TTS**，不能外推为真人粤语识别能力。
- 时间测量：E2 的 100% 档 `inference_seconds_per_sample=187.7s` 明显异常
  （同规模 E3 `k=all` 为 2.0s/样本），判断为该次运行期间机器被挂起导致
  `perf_counter` 失真 [受限]，**该单元格的耗时不作为结论**。
  可信的耗时为：84 模板 ≈345ms/样本、30 模板 ≈145ms/样本、397 模板 ≈2022ms/样本。
