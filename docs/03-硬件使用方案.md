# 03 · 硬件使用方案

> 目标：给出「桌面验证级」与「家居部署级」两套可落地的硬件方案，
> 含选型理由、BOM 成本表、接线与供电、拾音距离与噪声对策、部署步骤。
> 软件对硬件无强依赖：任何能录 16 kHz 单声道音频的设备均可接入。

## 1. 硬件需求分析（由软件反推）

| 软件环节 | 硬件需求 | 依据 |
|---|---|---|
| SenseVoice-Small ASR | 16 kHz 单声道拾音；CPU ≥ 4 核 ARM/x86，RAM ≥ 2 GB | 模型 fp32 约 900 MB，加载后内存约 1.2 GB；q8 量化约 250 MB 可降至 ~600 MB |
| FSMN-VAD | 低底噪麦克风 | 静音段误触发会浪费算力 |
| 语音反馈 TTS | 扬声器（3.5 mm / USB / I2S 功放） | pyttsx3 离线播报 |
| 执行适配 | 与家居设备同局域网（MQTT/HA）或红外发射 | 控制真实设备 |
| 交互 | 按键/网页按钮（本期不做唤醒词） | 控制范围，避免误触发 |

1. 麦克风置于桌面中央，距说话人 0.5~1 m；

### 3.2 接线与供电

```
USB-C 5V/3A ──→ Raspberry Pi 4B
                    │ 40-pin GPIO（I2S/ I2C / 3.3V）
                    ▼
            ReSpeaker 2-Mics HAT（叠装，无需杜邦线）
              ├── 板载双麦克风（朝上开孔）
              ├── 板载按键 → 触发录音（替代网页按钮）
              ├── 板载 LED ×3 → 录音/识别/执行状态指示
              └── 3.5 mm 输出 ──→ 有源音箱
Pi ──以太网/WiFi──→ 家用路由器 ──MQTT──→ 智能插座/灯泡/ESP32 红外
```

要点：
- HAT 与 Pi 通过 40-pin 直插，I2S 数字音频，**不要**用 USB 声卡转接（增加延迟与底噪）；
- 音箱接 HAT 的 3.5 mm 口（板载功放），避免 Pi 本体 PWM 音频的噪声；
- 麦克风孔上方勿遮挡；装置距电视 ≥ 1 m，减少背景声干扰；
- 供电必须 5V/3A，低功率充电头会在推理峰值时欠压重启。

### 3.3 拾音距离与噪声对策

| 配置 | 有效拾音距离 | 适用 |
|---|---|---|
| 2-Mic HAT | 1~2 m | 卧室/书房近场 |
| 4-Mic Array | 3~5 m（波束成形） | 客厅远场（推荐） |

- 软件侧已启用浏览器/驱动回声消除与噪声抑制；VAD 只送有效语音段；
- 电视大声播放时建议按按键触发（半双工），避免把电视声当指令；
- 装置摆放高度 0.8~1.2 m（桌面/柜面），避开墙角混响。

### 3.4 部署步骤（树莓派）

1. 烧录 Raspberry Pi OS (64-bit, Bookworm) 到 microSD，启用 SSH；
2. 安装 ReSpeaker HAT 驱动（seeed-voicecard），`arecord -l` 确认声卡；
3. `sudo apt install python3-venv libsndfile1 portaudio19-dev`；
4. 拷贝本项目，`python3 -m venv .venv && pip install -r requirements.txt`
   （ARM64 有 torch/funasr wheel；若个别包无 wheel，用 `--prefer-binary`）；
5. `python scripts/download_models.py`（ModelScope 国内源）；
6. 内存紧张时改用 q8 量化运行时（sherpa-onnx / funasr llama.cpp，见 docs/01 调研），
   或保持 fp32 但关闭桌面环境（`systemctl set-default multi-user.target`）；
7. `python src/dialect_home/server.py` 启动，局域网设备浏览器访问 `http://<pi-ip>:8000`；
8. 执行器切换：`config/settings.yaml` 中 `executor.type: mqtt`，指向局域网 MQTT broker
   （可在 Pi 上 `sudo apt install mosquitto`）。

## 4. 方案 C：超低成本替代（≈ ¥250，可选）

Orange Pi Zero 3（2 GB）+ USB 麦克风 + USB 音箱。
仅适合跑 q8 量化模型（~250 MB），fp32 内存不足；性能余量小，列为备选不推荐为主方案。

## 5. 硬件与软件的接口约定

- 音频：任意来源统一重采样为 **16 kHz / 单声道 / float32**（`audio.py`）；
- 触发：网页按钮 / CLI `--mic` / HAT 按键（GPIO 中断调用 `record()`，预留接口）；
- 执行：`executor.type` 三选一（simulator / mqtt / homeassistant），硬件增减不改识别代码；
- 反馈：3.5 mm / USB 音箱均可，pyttsx3 走系统默认输出设备。

## 6. 选型结论

- **课程演示与评测**：方案 A（现有 PC + USB 麦），零风险、指标可复现；
- **产品形态交付**：方案 B（Pi 4B 4GB + ReSpeaker 4-Mic + MQTT 执行端），
  核心 ¥675、含执行端 ≈ ¥810，满足 3~5 m 客厅远场与离线运行；
- 两套方案运行**同一套软件**，仅 `settings.yaml` 的执行器与音频输入不同。
