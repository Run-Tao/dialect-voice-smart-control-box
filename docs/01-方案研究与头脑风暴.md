# 01 · 方案研究与头脑风暴

> 项目：智能家居方言语音指令转换器（方言智居 / DialectHome）
> 定位：本科工程导论课程项目 · 独立研究与实现
> 日期：2026-11-20

## 1. 问题定义

把用户用**方言（以粤语为主，兼顾带口音普通话）**说出的自然口语指令，
转换为智能家居设备可执行的结构化控制命令，并给出语音反馈。

例：
- 粤语「唔该帮我熄咗客厅盏灯」→ `{device: light, room: 客厅, action: turn_off}`
- 粤语「冷气较低两度」→ `{device: 空调, action: temp_down, delta: 2}`
- 带口音普通话「把窗帘拉上」（n/l 不分、平翘舌不分）→ `{device: curtain, action: close}`

### 1.1 核心难点

| 难点 | 说明 |
|---|---|
| 方言声学差异 | 粤语有 6~9 声调、入声韵尾 -p/-t/-k，与普通话声学模型差异大 |
| 方言词汇/语法 | 粤语用「熄灯」不用「关灯」、「冷气」不用「空调」、「较」不用「调」、「拉埋」=「拉上」 |
| 口音普通话 | n/l、f/h、zh/z、ang/an 混淆导致通用 ASR 错字 |
| 口语噪声 | 「唔该」「帮我」「咗」「啲」等冗余词、语气词 |
| 资源约束 | 开发机无 GPU、无 MSVC 编译器；课程项目要求低成本、可离线演示 |
| 远场与噪声 | 真实家居环境 1~3 m 拾音、电视背景声 |

### 1.2 验收目标（可量化）

1. 合成测试集（TTS 粤语 + 普通话）意图识别准确率 ≥ 90%，槽位（房间/温度值）准确率 ≥ 85%；
2. 单条指令端到端延迟（CPU）≤ 3 s；
3. 全链路可离线运行（云端 API 仅作可选增强）；
4. 交付完整文档 + 可运行代码 + 实测测试报告 + 硬件使用方案。

> 口径声明：课程阶段无真实方言录音采集条件，指标基于 **TTS 合成语料**，
> 测试报告中会明确标注「合成口径」，并给出真实录音验证的后续方案。

## 2. 候选路线头脑风暴

### 路线 A：端到端微调方言 ASR
在 Whisper / Paraformer 上用粤语语料（Common Voice zh-HK、MDCC 等）微调。
- 优点：理论精度上限最高，可深度适配方言。
- 缺点：需要 GPU（本机无）；粤语标注语料获取与清洗成本高；微调数小时起步；
  课程周期内风险大；部署模型体积大。
- 结论：**否决为主路线**，列为后续工作。

### 路线 B：云端方言 ASR API
讯飞/百度/阿里等提供方言识别 API（讯飞宣称支持 20+ 方言）。
- 优点：开箱即用、精度高、免维护模型。
- 缺点：依赖网络（演示现场网络不可控）；按量付费；隐私（家居语音上云）；
  多数 API 的「方言」实为带口音普通话，纯粤语支持参差。
- 结论：**不作为主路线**，保留为可选后端接口（架构上留插槽）。

### 路线 C：本地多语 ASR + 方言鲁棒理解层（双层架构）
用原生支持粤语的开源多语模型做转写，再用「文本归一化 + 拼音模糊匹配 +
可配置命令库」吸收方言词汇与口音误差。
- 关键事实（调研核实）：**SenseVoice-Small**（阿里 FunAudioLLM，Apache-2.0）
  原生支持 zh / yue / en / ja / ko，约 2.34 亿参数，SAN-M 编码器 + CTC 头，
  **非自回归**，CPU 可实时（量化后模型约 250 MB，树莓派 4B 可跑）；
  官方明确「要粤语 → SenseVoice 原生支持」。
- 备用后端 faster-whisper（CPU int8），用于交叉验证与降级。
- 理解层不依赖 ASR 字面完全正确：把识别文本与命令库都映射到**模糊拼音域**
  （n/l、zh/z、ang/an 等混淆归一），用编辑距离/子串相似度匹配意图与槽位。
- 优点：离线、免费、CPU 友好、纯 Python wheel 可装（无 MSVC 需求）、
  命令库 YAML 可配置可扩展、对 ASR 错字有二次容错。
- 缺点：对完全未登录的说法需要扩命令库；理解层是规则+模糊匹配，不是开放域对话。
- 结论：**主路线**。家居指令是封闭域（几十条意图），规则+模糊匹配恰好够用且可控。

### 路线 D：关键词/模板 spotting
openWakeWord / Porcupine 训练固定关键词，或纯模板匹配。
- 优点：极低延迟、极低算力。
- 缺点：只能识别训练过的固定短语，方言说法千变万化，覆盖率差；
  自定义关键词训练仍需语料。
- 结论：**不作为识别主路线**；可选作唤醒层（「小方小方」），本期用按键/按钮替代唤醒以控范围。

### 路线 E：混合架构（C 为主干 + B 可选 + D 可选唤醒）
在 C 的基础上把 ASR 后端、执行器、TTS 都做成可插拔适配器。
- 结论：**最终采用**。既保证离线可演示，又为云端增强/真实设备接入留好接口。

|---|---|---|---|---|---|

| 开发周期风险 | 高 | 低 | 中 | 低 | 中 |

## 4. 最优计划（路线 E 落地）

**一句话**：SenseVoice-Small（粤语原生）做耳朵，拼音模糊理解层做大脑，
YAML 命令库做词汇表，可插拔执行器做手，离线 TTS 做嘴。

```
麦克风/网页录音/音频文件
        │ 16 kHz 单声道
        ▼
   FSMN-VAD 切段（去静音）
        ▼
   SenseVoice-Small ASR（language=auto，含 yue）
   [备用: faster-whisper small int8]
        ▼
   文本归一化：繁→简 · 粤语口语词映射 · 中文数字→阿拉伯数字
        ▼
   意图/槽位解析：房间别名 + 设备别名 + 动作短语
   （原文精确匹配 → 模糊拼音域匹配，双通道打分）
        ▼
   执行适配器：虚拟家居模拟器 / MQTT / Home Assistant
        ▼
   语音反馈（pyttsx3 离线）+ 日志与指标
```

关键设计决策与理由：
1. **ASR 选 SenseVoice 而非 Whisper**：Whisper 粤语训练数据少、易把粤语转成普通话书面语；
   SenseVoice 原生 yue 且非自回归，CPU 延迟低一个量级。
2. **理解层用「拼音模糊域」而非纯字面**：ASR 对口音普通话常输出同音错字
   （「窗帘」→「窗连」），拼音域 + 混淆归一可吸收这类错误；对粤语则先做
   词汇映射（熄→关、冷气→空调）再匹配。
3. **命令库外置 YAML**：新增设备/说法不改代码，课程答辩可现场演示扩展。
4. **执行层三适配器**：模拟器保证无硬件也能完整演示与自动化测试；
   MQTT/HA 对接真实家居；硬件方案文档给出选型。
5. **评测诚实口径**：TTS 合成语料（zh-HK 粤语声线 + zh-CN 普通话声线），
   报告标注合成口径，附真实录音验证规程。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| SenseVoice 把粤语口语词转写为近音字 | 归一化层 + 拼音模糊匹配双重容错；命令库收录口语别名 |
| CPU 推理慢 | 非自回归模型 + VAD 只送有效段；实测延迟写入报告 |
| 模型下载大（~900 MB fp32） | ModelScope 国内源；提供下载脚本与缓存目录 |
| 无真实方言语料 | 合成口径明示 + 真实录音采集与验证规程（docs/05） |
| 浏览器录音格式兼容 | 前端直接采 16k PCM 封装 WAV，不依赖 ffmpeg 解码 |
