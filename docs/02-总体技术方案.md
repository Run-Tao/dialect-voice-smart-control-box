## 2. 模块契约

| 模块 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `audio.py` | wav 路径 / ndarray / 麦克风 | `AudioClip(samples float32, sr=16000)` | `resample_poly` 重采样；`load_wav`/`save_wav`/`record` |
| `asr/base.py` | AudioClip | `AsrResult(text, language, backend, ms)` | 后端抽象接口 |
| `asr/sensevoice.py` | AudioClip | AsrResult | funasr AutoModel + fsmn-vad，`language="auto"`，`use_itn=True` |
| `asr/whisper_backend.py` | AudioClip | AsrResult | faster-whisper small int8 CPU，`language="zh"` |
| `asr/mock.py` | wav 旁车 `.txt` | AsrResult | 单元测试用，零模型依赖 |
| `normalize.py` | 原始文本 | 归一文本 | opencc t2s；粤语词表（熄→关、冷气→空调、较→调、拉埋→拉上…）；中文数字→数值（含廿/卅/两） |
| `understand.py` | 归一文本 + 命令库 | `Command(intent, device, room, slots, confidence)` 或 None | 双通道：原文子串匹配 + 模糊拼音域匹配 |
| `executor/*` | Command | `ExecResult(ok, message, state)` | simulator 维护设备状态；mqtt 发布 JSON；ha 调 REST 服务 |
| `tts.py` | 文本 | 播放/音频文件 | pyttsx3 离线优先；edge-tts 在线可选 |
| `pipeline.py` | 音频 | `PipelineResult`（各环节文本/命令/反馈/分段耗时） | 组装以上模块，写 JSONL 指标 |
| `server.py` | HTTP | JSON / 静态页 | `/api/recognize` `/api/state` `/api/command`（文本直输调试） |

## 3. 理解层算法（核心创新点）

封闭域指令理解，双通道打分取最优：

1. **原文通道**：归一化文本中直接子串命中设备/房间/动作别名（精确、置信度高）。
2. **拼音模糊通道**：
   - 文本与别名都转拼音（pypinyin，无声调）；
   - 混淆归一：`zh→z, ch→c, sh→s, n→l, ang→an, eng→en, ing→in, f→h`（口音等价类）；
   - 用 rapidfuzz 在整句拼音串上对别名拼音串做滑窗子串相似度；
   - 阈值过滤（默认 78/100），命中多个候选时按分数×别名长度加权取最优。
3. **槽位**：温度数值从归一文本正则提取（「二十六度」「26度」「两度」）；
   房间/设备本身即槽位。
4. **冲突消解**：设备决定意图域（light 的 on/off 与 ac 的 on/off 分开打分）；
   未识别设备但命中「开/关 + 房间」时不臆测，返回低置信并请求澄清。

## 5. 关键参数

| 参数 | 默认 | 依据 |
|---|---|---|
| 采样率 | 16 kHz 单声道 | SenseVoice/Whisper 输入要求 |
| VAD | fsmn-vad，max_single_segment_time=30000 | 官方推荐 ≤30s 段 |
| ASR 语言 | auto（可强制 yue/zh） | 粤普混说场景 |
| 模糊匹配阈值 | 78 | 评测脚本扫阈值定标 |
| 单次录音上限 | 15 s | 家居指令短句 |
| 端到端延迟目标 | ≤3 s (CPU) | 验收目标 |

## 6. 延迟预算（CPU，i5 级）

| 环节 | 预算 |
|---|---|
| 重采样+VAD | <100 ms |
| SenseVoice 转写（3~5s 音频） | 300~1200 ms |
| 归一化+理解 | <50 ms |
| 执行（模拟器/MQTT 本地） | <50 ms |
| 合计 | <1.5 s（实测见 docs/05） |
